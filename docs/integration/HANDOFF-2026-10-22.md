### Các giới hạn HTTP được giữ có chủ đích

- Actor phải lấy từ token đã được SDK xác minh, không lấy `subject`, org hoặc roles từ body.
- Claim hiện yêu cầu: `sub`, `organizationId`, `realm_access.roles`. Chưa đối chiếu claim thực tế của realm đã hoàn thành bootstrap.
- Thiếu/placeholder config trả `POLICY_UNAVAILABLE`; credential sai trả `UNAUTHENTICATED`.
- `POST /ideas`, `POST /reports` và mọi endpoint lấy identity envelope hiện **bị khóa** ở HTTP boundary, vì provenance của ciphertext và policy giải mã chưa kiểm chứng.
- Service vẫn có thể test nghiệp vụ bằng dữ liệu tổng hợp ở trong test. Không mở các endpoint bị khóa bằng cờ bypass để demo.
- Các thao tác nghiệp vụ hiện được kiểm ở lớp APP, chưa phải FABRIC/QEA.

## 5. Các việc còn dở — ưu tiên thực hiện tiếp

### P0 — Chạy được service integration tests

File: `tests/p1/helpers/db.ts`.

Trên máy cũ, `prisma db push` tới file SQLite tạm chưa tồn tại trả lỗi trống `Schema engine error`. Thử độc lập cho thấy tạo file rỗng trước khi push giúp lệnh chạy được. Helper hiện **chưa được sửa**.

Hướng sửa tối thiểu cần kiểm chứng: import `writeFileSync`, tạo `path.join(dir, "test.db")` trước `execFileSync` trong `createTempDb()`. Chỉ chạm database tạm do test vừa tạo, không reset database có dữ liệu.

Sau đó chạy `npm run test:p1`. Một số regression bên dưới đã được viết để phơi bày lỗi, nên có thể còn RED ngay cả khi setup đã sửa. Không xóa regression hoặc hạ điều kiện để ép xanh.

### P0 — Hai request mở danh tính đồng thời

File: `src/server/services/index.ts`, method `createUnmaskRequest`.

Kiểm tra request đang hoạt động nằm ngoài transaction; hai lời gọi đồng thời có thể tạo hai vòng rồi ghi đè pointer của report. **Chưa áp dụng fix.**

Hướng đã xác định: trong transaction dùng compare-and-swap trên report theo `id`, org, version và `votingRequestId` đã đọc; chỉ bên thắng được cập nhật pointer/tạo vòng. Bên thua trả `VERSION_CONFLICT` và không tạo orphan request. Cần kiểm chứng hành vi transaction của SQLite.

Thêm ràng buộc khi đọc report envelope: request được dùng phải trùng `report.votingRequestId` hiện hành, không chấp nhận một vòng READY cũ chỉ vì biết ID.

Regression đã thêm trong `tests/p1/services.integration.test.ts`:

- Hai lời gọi đồng thời chỉ tạo một vòng hoạt động.
- Vòng READY hết hạn không phát hành envelope và cho phép tạo vòng mới.
- Vòng READY không còn là vòng hiện hành không phát hành envelope.

HTTP envelope hiện bị khóa, nên không mở endpoint chỉ vì kiểm tra APP đã xanh.

### P0 — Cung cấp quyết định của từng voter

`VoterView.decision?: VoteDecision` đã thêm vào `src/contracts/api.ts`, nhưng `votingView()` trong service **chưa gán field này** từ `row.votes`.

UI adapter dùng quyết định thật để tạo `validApprovals[]`, không suy đoán người đã vote là đã APPROVE. Regression APPROVE/DENY đã thêm trong service test và đang chờ setup DB chạy được.

### P0 — Nối bridge factory với UI adapter

- Bootstrap hiện gọi `window.createVoiceVaultLiveRuntime()` không có tham số.
- `src/integration/bridge-entry.ts` vẫn chỉ export `window.createVoiceVaultLive` và `VoiceVaultLiveStubs` từ code P1 cũ.
- `src/integration/ui-runtime.ts` đã có mapper nhưng **chưa được bridge sử dụng**.

Cần tạo factory được cấu hình để bọc P1 runtime bằng UI adapter. Không chọn `createStubAuth`/`createStubCrypto` làm mặc định LIVE; stub crypto chỉ là base64 JSON. Khi thiếu adapter Tide thật, trả lỗi rõ và giữ tính năng nhạy cảm khóa.

`scripts/build-bridge.mjs` cũng đang kiểm global cũ; cập nhật smoke test cùng thay đổi factory. Factory/raw runtime dành cho test có thể giữ riêng, nhưng không công khai một chế độ fake thành LIVE đã được bảo vệ.

### P1 — Session hết hạn phải thực sự signed out

Trong `browser-runtime.ts`, `getSession()` hiện đổi API `UNAUTHENTICATED` thành `ok(sessionView())`; nếu auth adapter vẫn giữ authenticated=true thì UI có thể hiển thị connected sai.

Cần regression API 401 trong khi adapter còn session cũ; kết quả phải là signed out hoặc lỗi xác thực, không được xanh giả.

### P1 — Hoàn tất đối chiếu UI/API

- UI dùng capability objects; API P1 dùng capability arrays. Mapper mới giải quyết cơ bản.
- UI dùng `status`, `approvalCount`, `validApprovals[]`, nested `report.voting`; P1 dùng `state`, số `validApprovals`. Mapper có hydration qua `getVotingRequest`.
- UI council cần `capabilities.canPropose`; mapper hiện false vì council-change service chưa triển khai.
- Audit mapper đổi `occurredAt/source/resourceId` sang `createdAt/enforcement/targetId`.
- UI chỉ hiện Approve cho idea ENDORSED, nhưng P1 chưa có endorsement và quyết định trực tiếp UNDER_REVIEW. **Chưa chốt cách thể hiện khác biệt này**; không giả mạo trạng thái ENDORSED.
- Public credit và reveal vẫn chưa được kiểm chứng; mapper giữ canReveal=false.
- Cần test với DOM thật + payload từ service/adapter, không chỉ test mapper đơn lẻ.

## 6. Bắt đầu trên máy mới

```bash
git clone https://github.com/Neil-275/rmit_hackathon.git
cd rmit_hackathon
git switch master
git pull --ff-only origin master
npm ci
npm run db:generate
```

Nếu repo đã có sẵn, bảo toàn thay đổi local trước rồi fetch/pull; không dùng reset hard.

Tạo `.env` local cho SQLite nếu cần chạy app/database:

```dotenv
DATABASE_URL="file:./local/dev.db"
```

Prisma resolve đường dẫn theo schema; file nằm dưới `prisma/local/`. Chỉ chạy `npm run db:push` với database local phù hợp. Test dùng database tạm riêng và không cần mượn database app.

